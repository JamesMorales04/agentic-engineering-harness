## REAL_PROVIDER lane

**Status from the audit:** not established for the complete claimed capability matrix.

A real-provider claim requires a freshly packed candidate, provider startup and execution receipts, current candidate/build identity, deterministic oracle checks, and required independent review. Deterministic fixtures and contract tests cannot certify real providers.

The audit identifies incomplete or unproven real-provider journeys for semantic assessment, Librarian research, Paseo, Podman/OCI isolation, integration environments, browser validation, delivery/reconciliation, and the full capability matrix. S2 deterministic Paseo fakes do not change that status. The Serena smoke recorded in the historical ledger proves only the tested Serena MCP broker path; it does not certify unused provider lease/release lifecycle or model execution.

## Reconciled claims

- **Authority and HumanDecision:** deterministic recording is not consumption. HumanDecision has no production consumer; the Control Center UI sends the wrong field and has no decision call site. Authority/HumanDecision is not PASS.
- **Cancellation:** cancellation is not fully proven to require current controller epoch ownership. Terminalizing an operation without current-owner proof remains an authority gap.
- **Validation, review, and acceptance:** these are separate gates. Validation PASS and quality/review success are not final acceptance. Managed Lead acceptance is deferred, a complete production AcceptanceOracle path is missing, and managed delivery can occur before acceptance.
- **CandidateImpact:** actual impact assessment is not yet consumed to recompile reviewers, validation, and acceptance. requiresIndependentReview is evidence, not proof that an independent reviewer was assigned.
- **Repairer:** candidate-assembly repair support exists, so the public path is not accurately described as having no Repairer mutation support. The remaining gap is complete frozen Repairer assignment and end-to-end operation-state integration for repair, assurance, and acceptance.
- **StructuredResult provenance:** candidate/generation/epoch checks exist, and blueprint/policy checks are optional in some paths. Production launchers omit required full digests; do not describe provenance as wholly absent or complete.
- **ExecutionCatalog:** the catalog exists and is used. Its policy/tool authorization fields are not fully enforced; do not describe the catalog itself as absent.
- **Packed campaign:** some campaign tests import source directly. Do not label all campaign tests or all product journeys packed.
- **Serena:** the historical smoke covers the tested Serena broker path only, not provider-lease lifecycle or real-model certification.
- **Dated validation counts:** retain them only as dated checkpoint evidence in the ledger. They are not rerun results or current certification.
- **PR description in src/delivery/finalize.ts:** its claim that Lead acceptance preceded PR creation is overbroad for the managed path, which can deliver before managed Lead acceptance.

## Certification rule

CertificationCore evaluates frozen policy against candidate/build-bound receipts and required evidence. It does not infer provider success from deterministic tests, browser success from adapter contracts, adversarial robustness from ordinary negative tests, or packed-candidate behavior from direct-source test imports. Each lane reports its own status and evidence.
