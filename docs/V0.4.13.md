# v0.4.13 — Built-in Default Agent Pack

v0.4.13 makes agent topology reusable even when a target repository has never had a `.harness/` directory. The package now ships a built-in `aeh:default` topology and `aeh init` creates a small project overlay that extends it instead of copying the entire agent catalog.

## Why a built-in pack

A project should not have to maintain a large agent JSON file merely to obtain sensible engineering roles. At the same time, defaults must not become immutable framework magic. The topology therefore uses explicit layer composition:

```jsonc
{
  "version": 1,
  "extends": ["aeh:default"],
  "agents": {},
  "routing": [],
  "remove": { "agents": [] }
}
```

The effective topology is deterministic and inspectable through `aeh agents compile`, `aeh agents check`, `aeh agents list`, `aeh agents show`, and `aeh agents route`.

## Default agents

The built-in pack deliberately includes cross-project engineering roles rather than copying every project-specific Pawra role.

### Control and discovery

- `lead` — orchestration, intent ownership and final semantic acceptance (`@brain`).
- `planner` — read-only decomposition and dependency planning (`@brain`).
- `oracle` — read-only diagnosis and exception classification (`@brain`).
- `explorer` — cheap repository discovery (`@workhorse`).
- `librarian` — authoritative documentation/research support (`@workhorse`).

### Implementers

- `implementation-worker` — generic fallback.
- `backend-implementer`
- `frontend-implementer`
- `data-implementer`
- `mobile-implementer`
- `test-implementer`
- `docs-implementer`
- `ops-implementer`
- `quality-implementer` — focused review-debt remediation.
- `senior-implementer` — stronger `@brain` remediation.

### Reviewers

- `code-quality-reviewer`
- `requirements-reviewer`
- `architecture-reviewer`
- `security-reviewer`
- `api-reviewer`
- `backend-reviewer`
- `frontend-reviewer`
- `data-reviewer`
- `mobile-reviewer`
- `test-reviewer`
- `docs-reviewer`
- `ops-reviewer`

### Validation

- `validator`
- `integration-validator`
- `e2e-validator`

Agents that are tightly coupled to one external workflow are intentionally not universal defaults. In particular, `openspec-manager` is redundant with the Harness SDD/QuickContract normative layer, while `github-manager` would make generic engineering execution depend on a GitHub-specific write surface. Projects may add either as ordinary local agents when appropriate.

## Model defaults

The pack preserves the brain/workhorse hierarchy:

```jsonc
"models": {
  "brain": {
    "runtime": "codex",
    "provider": "openai",
    "model": "gpt-5.6-luna",
    "variant": "max"
  },
  "workhorse": {
    "runtime": "opencode",
    "provider": "opencode-go",
    "model": "deepseek-v4-flash"
  }
}
```

Changing an alias once changes every inherited agent that uses it.

## Four composition operations

### 1. Use the defaults unchanged

```jsonc
{
  "version": 1,
  "extends": ["aeh:default"]
}
```

### 2. Add an agent

```jsonc
{
  "version": 1,
  "extends": ["aeh:default"],
  "agents": {
    "payments-implementer": {
      "role": "implementer",
      "domains": ["payments"],
      "execution": { "model": "@workhorse" },
      "permissions": {
        "read": "allow",
        "write": "allow",
        "shell": "allow"
      },
      "outputContract": "implementer"
    }
  },
  "routing": [
    {
      "id": "payments",
      "priority": 90,
      "when": { "intent": "implement", "domains": ["payments"] },
      "use": "payments-implementer"
    }
  ]
}
```

### 3. Partially override a default agent/model

Local definitions merge onto inherited definitions, so the project only specifies what changes:

```jsonc
{
  "version": 1,
  "extends": ["aeh:default"],
  "models": {
    "workhorse": { "model": "another-model" }
  },
  "agents": {
    "backend-implementer": {
      "temperature": 0.05,
      "description": "Project-specific backend charter"
    }
  }
}
```

Nested `execution`, `permissions`, runtime `capabilities`, and model `options` are merged rather than replacing the entire parent object. A routing rule with an existing `id` replaces that inherited rule.

### 4. Remove defaults

`remove` accepts minimatch patterns:

```jsonc
{
  "version": 1,
  "extends": ["aeh:default"],
  "remove": {
    "agents": ["mobile-*", "ops-reviewer"],
    "routing": ["mobile"]
  }
}
```

Removing an agent also removes references to it from inherited routing/recovery/council membership. The effective topology is validated after composition, so remaining references to removed models/runtimes or incomplete newly-added definitions still fail deterministically.

## Multiple layers

`extends` is ordered. Later bases override earlier bases, then the current project layer is applied:

```jsonc
{
  "version": 1,
  "extends": [
    "aeh:default",
    "../company/agents.jsonc"
  ]
}
```

Relative extension paths are resolved relative to the file declaring them. Circular extension chains are rejected.

## Agent charters are executable context

The `description` field is now propagated into `AgentExecutionSelection` and prepended to routed agent prompts. It is therefore a concise role charter rather than decorative metadata. Permissions and deterministic output contracts remain the enforcement boundary; the charter explains the specialist's engineering responsibility inside that boundary.

## Self-hosting / dogfooding

The Harness repository itself now contains:

```text
.harness/
├── project.yaml
└── agents.source.jsonc
```

Its topology extends `aeh:default` and adds a repository-specific `harness-reviewer`. Runtime artifacts such as generated topology, runs, reports, findings, seals and provenance remain ignored by Git.

This makes the Harness its own reference project without duplicating the built-in catalog.
